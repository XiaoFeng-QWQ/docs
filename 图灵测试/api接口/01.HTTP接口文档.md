# HTTP API 文档

> 项目：对面是AI吗  
> 协议：HTTP/1.1  
> Content-Type：`application/json`（除标注外）  
> 基础URL：`https://game.xfcode.top`  
> 更新日期：2026-08-20

---

## 认证机制

大部分需要身份的 API 使用 **Bearer Token** 认证：

- **请求头**：`Authorization: Bearer <token>`
- **Token 类型**：JWT（HMAC-SHA256，密钥为玩家的 password_hash，有效期 365 天）
- **获取方式**：创建/恢复身份时下发
- **特点**：修改密码后旧 token 自动失效（密钥变化）

**需要认证的 API**（共 24 个）：
`/api/upload-userdata`、`/api/chat-history`、`/api/chat-history/detail`、`/api/chat-history/collect`、`/api/collection/like`、`/api/player-messages`、`/api/player-message/hide`、`/api/player-message/settings`、`/api/sticker/list`、`/api/sticker/upload`、`/api/sticker/delete`、`/api/generate-player-id`（仅 `action=change_password` 时需要）、
`/api/bot/panel`、`/api/bot/panel/nickname`、`/api/bot/panel/key`、`/api/bot/apply`、`/api/bot/stickers`、
`/api/temp/users`、`/api/temp/invite`、`/api/temp/invite/decline`、
`/api/macros`、`/api/macros/delete`、
`/api/player/tags`、`/api/player/worn-tags`、
`/api/weekly-report`

**不需要认证的 API**：其余为公开接口或通过昵称+密码手动验证。

## 通用错误响应

所有 API 在认证失败时返回：

```json
{"error": "缺少 token"}
{"error": "token 无效或已过期"}
```

## 1. 身份与账号

> **源码位置**：[GameController.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Controllers/GameController.php)（generate-player-id/player-stats/upload-userdata 接口） · 路由定义见 [Router.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Core/Router.php)

### 1.1 获取/恢复玩家身份

```
GET /api/generate-player-id
```

**说明**：创建新身份、恢复已有身份、修改密码、查询战绩的复合接口。

**请求参数（Query）**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 否 | `recover`（恢复）、`change_password`（改密码）、空（查询） |
| `nickname` | string | 条件 | 恢复时必填，1-16 字符 |
| `password` | string | 条件 | 恢复时必填（原密码），改密码时传 `old_password` 和 `new_password` |
| `old_password` | string | 条件 | 改密码时的旧密码 |
| `new_password` | string | 条件 | 改密码时的新密码，至少 6 位 |
| `fp` | string | 否 | 设备指纹，用于 IP+指纹联合查找 |

**请求头**：改密码时必须带 `Authorization: Bearer <token>`

---

**场景一：通过 Token 查询战绩**

```bash
curl "https://game.xfcode.top/api/generate-player-id" \
  -H "Authorization: Bearer <token>"
```

**响应** `200`：game.xfcode.top
```json
{
  "stats": {
    "total_games": 42,
    "wins": 18,
    "losses": 20,
    "draws": 4,
    "style_tags": ["理性", "幽默"],
    "title": "老玩家"
  }
}
```

---

**场景二：通过 IP+指纹恢复战绩**

```bash
curl "https://game.xfcode.top/api/generate-player-id?fp=<设备指纹>"
```

**响应** `200`：
```json
{
  "stats": { "total_games": 42, "wins": 18, "losses": 20, "draws": 4 }
}
```

---

**场景三：密码恢复身份**

```bash
curl "https://game.xfcode.top/api/generate-player-id?action=recover&nickname=小明&password=123456"
```

**成功** `200`：
```json
{
  "token": "eyJ...",
  "nickname": "小明",
  "stats": { "total_games": 42, "wins": 18, "losses": 20, "draws": 4 }
}
```

**玩家不存在** `200`：
```json
{"error": "玩家不存在"}
```

**密码错误** `200`：
```json
{"error": "密码不正确"}
```

---

**场景四：修改密码**

```bash
curl "https://game.xfcode.top/api/generate-player-id?action=change_password&old_password=123456&new_password=654321" \
  -H "Authorization: Bearer <token>"
```

**成功** `200`：
```json
{"ok": true}
```

**密码过短** `200`：
```json
{"error": "新密码至少 6 位"}
```

**旧密码错误** `200`：
```json
{"error": "旧密码不正确"}
```

---

**场景五：无匹配**

```json
{"error": "未找到玩家"}
```

### 1.3 上传本地用户数据

```
POST /api/upload-userdata
```

**说明**：将本地 UserData 同步到服务端。

**认证**：需要 `Authorization` 请求头。

**请求体（JSON）**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `nickname` | string | 是 | 昵称，1-16 字符 |
| `fp` | string | 否 | 设备指纹 |
| `stats` | array | 否 | 统计数据数组 |

**请求示例**：

```bash
curl -X POST "https://game.xfcode.top/api/upload-userdata" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"nickname":"小明","fp":"abc123","stats":[{"key":"wins","value":10}]}'
```

**成功** `200`：
```json
{"success": true, "message": "数据上传成功"}
```

**失败** `200`：
```json
{"error": "上传失败: <错误详情>"}
```


## 7. 管理员

### 7.1 管理员登录

```
POST /{adminPath}/api/login
```

**说明**：`{adminPath}` 默认值为 `/admin`，可在配置中修改。注意此接口不走 Bearer Token，使用用户名+密码。

**请求体（JSON）**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `username` | string | 是 | 管理员用户名 |
| `password` | string | 是 | 管理员密码 |

**请求示例**：

```bash
curl -X POST "https://你的域名/admin/api/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"xxx"}'
```

**成功** `200`：
```json
{
  "ok": true,
  "token": "eyJ...",
  "username": "admin",
  "role": "super_admin"
}
```

**失败**：
```json
{"ok": false, "error": "用户名和密码不能为空"}
{"ok": false, "error": "用户名或密码错误"}
{"ok": false, "error": "该账号已被禁用"}
```

**Token 说明**：
- 管理员 Token 有效期 24 小时
- 签名密钥为 `Admin.Password` 配置项
- Payload 包含 `admin_id`、`username`、`role`

## 8. BOT 面板

BOT 系统允许玩家申请一个 AI 机器人，BOT 可以以独立身份加入聊天室并发言。每个 BOT 拥有独立的 `bot_key` 用于 WebSocket 鉴权。

> **源码位置**：[GameController.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Controllers/GameController.php)（BOT 面板/申请/表情接口） · [BotGatewayWebSocketHandler.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Core/WebSocket/BotGatewayWebSocketHandler.php)（BOT 网关） · [bot-panel/index.html](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/Public/bot-panel/index.html)（前端）

```
GET /bot-panel
```

**说明**：BOT 管理面板页面，返回 HTML 页面。

### 8.2 获取 BOT 信息

```
GET /api/bot/panel
```

**认证**：需要 `Authorization` 请求头。

**说明**：获取当前玩家绑定的 BOT 信息。

**请求示例**：

```bash
curl "https://game.xfcode.top/api/bot/panel" \
```

### 10.4 宏触发语法

宏在聊天室消息中通过以下语法触发：

```
[!触发宏:名称]
[!触发宏:名称:参数值1|参数值2]
[!触发宏:昵称]
[!触发宏:昵称:参数值1|参数值2]
```

- 名称优先匹配昵称（nick），再匹配名称（name）
- 参数值用 `|` 分隔，按顺序对应宏定义的 `params`
- 模板内 `{参数名}` 会被替换为对应参数值
- 展开深度上限 3 层，防止递归死循环

## 13. OAuth 快捷登录

OAuth 2.0 快捷登录系统支持通过第三方平台（如 GitHub）快速登录/注册，使用 PKCE 授权码流程。

> **源码位置**：[OAuthController.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Controllers/OAuthController.php)（PKCE 授权码流程） · [GenericOAuthProvider.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Services/OAuth/GenericOAuthProvider.php)（提供商抽象） · [OAuthBindingRepository.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Services/Repository/OAuthBindingRepository.php)（绑定存取）

### 13.2 发起 OAuth 登录

```
GET /oauth/login/{provider}
```

**说明**：跳转到第三方 OAuth 授权页面。`{provider}` 为提供商 ID（如 `github`）。

**服务端处理**：
1. 生成 PKCE `code_verifier` 和 `code_challenge`
2. 生成随机 `state` 参数防 CSRF
3. 302 跳转到第三方 OAuth 授权 URL
4. 临时数据（state、code_verifier、redirect）存入 Redis，10 分钟过期

**请求参数（Query）**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `token` | string | 否 | 玩家 Token（绑定模式：已登录玩家绑定第三方账号时传） |
| `redirect` | string | 否 | 登录成功后的回调页面 URL |
| `bind` | int | 否 | `1`=绑定模式（需要传 token），`0`=登录模式 |

**绑定模式**：已登录玩家通过 `bind=1` 将第三方账号绑定到现有账号。
**登录模式**：未登录玩家通过 OAuth 创建新账号或登录已有绑定账号。

---

### 13.3 OAuth 回调

```
GET /oauth/callback/{provider}
```

**说明**：第三方 OAuth 授权后的回调地址。`{provider}` 为提供商 ID。

**请求参数（Query）**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | string | 是 | 授权码（provider 回调携带） |
| `state` | string | 是 | 状态参数（校验 CSRF） |

**处理流程**：
1. 校验 `state` 参数与 Redis 中的一致
2. 用 `code` + `code_verifier` 向 provider 换取 `access_token`
3. 用 `access_token` 获取第三方用户信息
4. 查找是否已有绑定记录：
   - 有绑定 → 直接返回玩家 Token（自动登录）
   - 无绑定 → 返回临时标识，引导玩家创建/绑定账号
5. 返回携带临时标识的 HTML 页面
