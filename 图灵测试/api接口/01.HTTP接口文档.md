# HTTP API 文档

> 项目：对面是AI吗  
> 协议：HTTP/1.1  
> Content-Type：`application/json`（除标注外）  
> 基础URL：`https://game.xfcode.top`  
> 更新日期：2026-10-06

---

## 时间格式约定

全站时间**唯一格式为 Unix 秒级时间戳（整数）**：

- **存储**：MySQL / SQLite 时间列一律 `BIGINT` / `INTEGER`（Redis、消息 JSON 同理）。
- **API 返回**：所有时间字段（`created_at`、`updated_at`、`last_played_at`、`saved_at`、`favorited_at`、`generated_at`、`period_start`、`period_end` 等）均为秒级整数，展示格式由消费端自行解析（前端统一用 `shared.js` 的全局 `XQFTime`）。
- **例外**：`duration` / `timeout` / `seconds` / `expires_in` / `cooldown` 等是**相对时长（秒）**，不是时间戳；日历业务键（`week`、`date`）、HTTP `Last-Modified` / `ETag` 等按格式要求保留原样。

> 下文各示例中的时间字段均为整数；若为相对时长会在字段说明中标注。

## 认证机制

大部分需要身份的 API 使用 **Bearer Token** 认证：

- **请求头**：`Authorization: Bearer <token>`
- **Token 类型**：自签 JWT（HMAC-SHA256，密钥为玩家的 `password_hash`，有效期 365 天）
- **获取方式**：`POST /api/email/auth`、`POST /api/oauth/confirm-create`、`GET /api/oauth/complete`、`/api/generate-player-id?action=recover` 等身份入口下发
- **特点**：修改密码后旧 token 自动失效（签名密钥变化），此时会下发新 token

**需要认证的 API（共 45 个）**：

`/api/chat-history`、`/api/chat-history/detail`、`/api/player-messages`、`/api/player/tags`、`/api/sticker/list`、
`/api/soup/my-puzzles`（GET 列表）、`/api/account/overview`、`/api/account/bot-access`、`/api/bot/panel`、`/api/oauth/bindings`、`/api/community/my`、
`/api/player-message/hide`、`/api/player-message/settings`、`/api/player/worn-tags`、`/api/chat-history/collect`、`/api/collection/like`、
`/api/sticker/upload`、`/api/image/upload`、`/api/sticker/delete`、`/api/sticker/add-to-mine`、
`/api/macros`（POST 保存）、`/api/macros/delete`、`/api/soup/my-puzzles`（POST 新建）、`/api/soup/my-puzzles/{id}/share`、`/api/soup/public-puzzles/{id}/copy`、
`/api/temp/invite`、`/api/temp/invite/decline`、`/api/bot/apply`、
`/api/account/nickname`、`/api/account/avatar`、`/api/account/password`、`/api/account/email`、
`/api/bot/panel/nickname`、`/api/bot/panel/key`、
`/api/community/post/save`、`/api/community/post/delete`、`/api/community/like`、`/api/community/favorite`、
`/api/community/comment`、`/api/community/comment/delete`、`/api/community/report`、
`/api/oauth/unbind`、`/api/oauth/sync-avatar`、
`/api/soup/my-puzzles/{id}`（PUT）、`/api/soup/my-puzzles/{id}`（DELETE）

**条件认证**：

- `/api/generate-player-id`：仅 `action=change_password`（以及带 `Authorization` 头查询战绩时）需要 token
- `/api/email/send-code`：`scene=bind_email` 时需要 token，`scene=auth` 不需要

**可选认证**（带 token 时行为不同，不带也能访问）：

- `/api/macros`：带 token 时返回的宏带 `mine` 标记
- `/api/temp/users`：带 token 时搜索结果排除自己
- 社区读接口 `/api/community/posts`、`/api/community/search`、`/api/community/post`、`/api/community/comments`：带 token 时返回 `liked` / `favorited` / `is_own` 等互动状态

**BOT KEY 认证**：

- `/api/bot/stickers`：不走玩家 token，采用 `player_id` 查询参数 + `Authorization: Bearer <bot_key>`（BOT 的独立密钥，见 BOT 面板）

**免认证**：其余公开接口、页面路由与静态资源；部分接口通过昵称+密码手动校验（如 `/api/player-stats`）。

## 通用错误响应

需要玩家 token 的接口（`requirePlayerId`）认证失败时返回：

```json
{"error": "缺少 token"}
{"error": "token 无效或已过期"}
```

交流社区写接口未登录时返回 **HTTP 401**：

```json
{"error": "请先登录后再操作"}
```

OAuth 相关接口（`requirePlayerId`）认证失败时返回：

```json
{"ok": false, "error": "缺少 token"}
{"ok": false, "error": "token 无效或已过期"}
```

## 1. 身份与账号

> **源码位置**：[GameController.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Controllers/GameController.php)（generate-player-id / player-stats / player-profile） · 路由定义见 [Router.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Core/Router.php)

### 1.1 获取/恢复玩家身份

```
GET /api/generate-player-id
```

**说明**：通过 Token 查询战绩、通过 IP+指纹恢复、密码恢复身份、修改密码的复合接口。

> 「代号 + 密码」注册入口已下线：`action=register` 会直接返回引导文案，注册请改用邮箱验证码（`POST /api/email/auth`）。

**请求参数（Query）**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 否 | `recover`（恢复）、`change_password`（改密码）、`register`（已下线）、空（查询） |
| `nickname` | string | 条件 | 恢复时必填，最长 16 字符 |
| `password` | string | 条件 | 恢复时的原密码 |
| `old_password` | string | 条件 | 改密码时的旧密码 |
| `new_password` | string | 条件 | 改密码时的新密码（走 `PasswordPolicy`，见 7.4） |
| `fp` | string | 否 | 设备指纹，用于 IP+指纹联合查找 |

**请求头**：改密码时（及通过 Token 查询时）必须带 `Authorization: Bearer <token>`

---

**场景一：通过 Token 查询战绩**

```bash
curl "https://game.xfcode.top/api/generate-player-id" \
  -H "Authorization: Bearer <token>"
```

**响应** `200`：
```json
{
  "stats": {
    "total_games": 42,
    "wins": 18,
    "losses": 20,
    "draws": 4,
    "last_played_at": 1751000000
  }
}
```

---

**场景二：通过 IP+指纹恢复战绩**

```bash
curl "https://game.xfcode.top/api/generate-player-id?fp=<设备指纹>"
```

**响应** `200`：
```json
{
  "stats": { "total_games": 42, "wins": 18, "losses": 20, "draws": 4 }
}
```

---

**场景三：密码恢复身份**

```bash
curl "https://game.xfcode.top/api/generate-player-id?action=recover&nickname=小明&password=Abc12345"
```

**成功** `200`：
```json
{
  "token": "eyJ...",
  "nickname": "小明",
  "stats": { "total_games": 42, "wins": 18, "losses": 20, "draws": 4 }
}
```

**昵称不存在或密码错误** `200`（不区分，防枚举昵称）：
```json
{"error": "用户名或密码错误"}
```

---

**场景四：修改密码**

```bash
curl "https://game.xfcode.top/api/generate-player-id?action=change_password&old_password=Abc12345&new_password=Xyz98765" \
  -H "Authorization: Bearer <token>"
```

**成功** `200`（密码已改，旧 token 失效，下发新 token）：
```json
{"ok": true, "token": "eyJ..."}
```

**新密码强度不足** `200`（文案来自 `PasswordPolicy`，见 7.4）：
```json
{"error": "密码至少 8 位"}
```

**旧密码错误** `200`：
```json
{"error": "旧密码不正确"}
```

---

**场景五：注册入口已下线 / 无匹配**

```json
{"error": "注册方式已升级，请使用邮箱验证码注册"}
```
```json
{"error": "未找到玩家"}
```

### 5.5 图片上传（聊天室图床代理）

```
POST /api/image/upload
```

**认证**：需要 `Authorization` 请求头。

**Content-Type**：`multipart/form-data`

**说明**：把图片代理上传到图床，**图床 URL 不下发**，仅返回一次性 `key`；由 `lobby_image` 消息内部消费 `key` 换取图片地址，客户端无法伪造图片地址。不入库。

**请求表单字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file` | file | 是 | 图片文件 |
| `file_ext` | string | 否 | 扩展名，缺省从文件名后缀推断，再缺省 `png` |
| `fp` | string | 否 | 设备指纹（用于封禁检查） |

**限制**：
- 同一玩家 60 秒内最多 10 次，超出返回 `{"error": "上传太频繁，请稍后再试"}`
- 返回的 `key` 为**一次性凭证，有效期 120 秒**，且与提交玩家绑定

**成功** `200`：
```json
{"success": true, "key": "a1b2c3d4e5f6..."}
```

**错误** `200`：
```json
{"error": "您已被管理员封禁"}
{"error": "上传太频繁，请稍后再试"}
{"error": "图片上传失败，请重试"}
{"error": "图片读取失败"}
{"error": "图床未配置"}
{"error": "图床上传失败，未获取到有效URL"}
```

## 6. 头像

### 6.1 获取玩家头像

```
GET /api/avatar/{player_id}
```

**说明**：公开接口，无需认证。返回玩家头像图片（WebP）。

**响应头**：
- `Content-Type: image/webp`
- `Cache-Control: public, no-cache`
- `ETag` / `Last-Modified`（支持 304 协商缓存）

**响应**：
- `200`：头像二进制内容
- `304`：`If-None-Match` / `If-Modified-Since` 命中时
- `404`：玩家无头像（返回纯文本 `Not Found`，前端降级为首字符渲染）

**说明**：上传入口见「7.3 上传头像」`POST /api/account/avatar`。

### 7.4 修改 / 首次设置密码

```
POST /api/account/password
```

**认证**：需要 `Authorization` 请求头。

**说明**：语义与 WS 通道 `change_password` / `set_password` 一致：
- `password_set=1`（已设置过密码）：必须提供正确的 `old_password`；
- `password_set=0`（OAuth / 邮箱注册的随机密码）：免旧密码直接设置。

密码变更后旧 token 失效，故返回新 token。

**请求体（JSON）**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `new_password` | string | 是 | 新密码，走 `PasswordPolicy` |
| `old_password` | string | 条件 | `password_set=1` 时必填 |

**密码策略**（`App\Services\Auth\PasswordPolicy`，仅约束新设置的密码）：至少 8 位；拒绝纯数字、6 位以上连续字符（`123456` / `abcdef` / `qwerty`）、单字符重复与常见弱口令；需包含字母、数字、符号中的两类（纯中文口令 ≥2 个汉字可豁免）。

**成功** `200`：
```json
{
  "ok": true,
  "token": "eyJ...",
  "player_id": "abc123...",
  "nickname": "小明",
  "password_set": true
}
```

**错误** `200`：
```json
{"error": "密码不能为空或只包含空白字符"}
{"error": "密码不能包含换行、制表符等控制字符"}
{"error": "密码至少 8 位"}
{"error": "密码过长，请控制在 72 字节以内"}
{"error": "密码不能是同一个字符的重复"}
{"error": "密码不能包含 6 位以上连续字符（如 123456、abcdef、qwerty）"}
{"error": "密码太常见了，容易被猜到，请换一个"}
{"error": "密码需至少包含字母、数字、符号中的两类"}
{"error": "请输入当前密码"}
{"error": "旧密码不正确"}
{"error": "你已设置过密码，请刷新后重试"}
```

### 11.4 宏触发语法

```
[!触发宏:名称]

```

- 名称优先匹配昵称（nick），再匹配名称（name）

- 模板内 `{参数名}` 会被替换为对应参数值
- 展开深度上限 3 层，防止递归死循环

## 17. OAuth 快捷登录

OAuth 2.0 快捷登录系统支持通过第三方平台（如 GitHub）快速登录/注册，使用 PKCE 授权码流程。登录结果产出现有的 player token（localStorage 存储），不引入 session/cookie。

> **源码位置**：[OAuthController.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Controllers/OAuthController.php)（PKCE 授权码流程） · [GenericOAuthProvider.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Services/OAuth/GenericOAuthProvider.php)（提供商抽象） · [OAuthBindingRepository.php](https://github.com/XiaoFeng-QWQ/TuringTalk/blob/master/App/Services/Repository/OAuthBindingRepository.php)（绑定存取）

### 17.1 支持的提供商

```
GET /api/oauth/providers
```

**说明**：公开接口，无需认证。未配置 `ClientId` 或端点不完整的 provider 不会返回。

**请求示例**：

```bash
curl "https://game.xfcode.top/api/oauth/providers"
```

**成功** `200`（直接返回数组）：
```json
[
  {"key": "github", "name": "GitHub"}
]
```

---

### 17.2 发起 OAuth 登录

```
GET /oauth/login/{provider}
POST /oauth/login/{provider}
```

**说明**：跳转到第三方 OAuth 授权页面。`{provider}` 为提供商 ID（如 `github`）。未知 / 不可用的 provider 返回 `404 Unknown OAuth provider`。

**服务端处理**：
1. 生成 PKCE `code_verifier` 和 `code_challenge`
2. 生成随机 `state` 参数防 CSRF
3. 302 跳转到第三方 OAuth 授权 URL
4. 临时数据（state、code_verifier、redirect、可选 bind_player_id）存入 Redis，**600 秒**过期

**请求参数（Query 或 form body，POST 场景用 form）**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `redirect` | string | 否 | 登录成功后的站内跳转路径（仅允许以 `/` 开头的同站路径） |
| `bind` | int | 否 | `1`=绑定模式（需已登录），缺省为登录模式 |
| `token` | string | 条件 | 绑定模式的玩家 Token（form POST 时用，无法带 Authorization 头） |

**绑定模式**：已登录玩家通过 `bind=1` 将第三方账号绑定到现有账号，须经 `Authorization: Bearer` 或 form `token` 解析出玩家；失效时返回 `{"ok": false, "error": "登录状态已失效，请重新登录后再绑定"}`。

**登录模式**：未登录玩家通过 OAuth 创建新账号或登录已有绑定账号。

---

### 17.3 OAuth 回调

```
GET /oauth/callback/{provider}
```

**说明**：第三方 OAuth 授权后的回调地址。`{provider}` 为提供商 ID。

**请求参数（Query）**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | string | 是 | 授权码（provider 回调携带） |
| `state` | string | 是 | 状态参数（校验 CSRF） |

**处理流程**：
1. 校验 `state`（一次性，取后即删）与 Redis 中的一致、provider 匹配
2. 用 `code` + `code_verifier` 向 provider 换取 `access_token`
3. 用 `access_token` 获取第三方用户信息
4. 分支处理：
   - **已绑定** → 生成一次性 exchange code，302 回到 `redirect`（携带 `oauth_code`）
   - **绑定模式** → 关联到已登录玩家，`bind` 失败则 302 携带 `oauth_error=该 OAuth 账号已绑定其他玩家`
   - **按邮箱匹配到已有玩家** → 自动绑定并登录
   - **邮箱未匹配** → 302 回 `redirect` 携带 `pending_code`，引导确认建号

**错误响应**：`400 Missing code or state` / `400 Invalid or expired state` / `400 Provider mismatch`；业务失败时 302 携带 `oauth_error=<消息>`。

## 19. 管理员

### 19.1 管理员登录

```
POST /{adminPath}/api/login
```

**说明**：`{adminPath}` 默认值为 `/admin`，可在配置中修改。注意此接口不走 Bearer Token，使用用户名+密码。

**请求体（JSON）**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `username` | string | 是 | 管理员用户名 |
| `password` | string | 是 | 管理员密码 |

**请求示例**：

```bash
curl -X POST "https://你的域名/admin/api/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"xxx"}'
```

**成功** `200`：
```json
{
  "ok": true,
  "token": "eyJ...",
  "username": "admin",
  "role": "super_admin"
}
```

**失败** `200`：
```json
{"ok": false, "error": "用户名和密码不能为空"}
{"ok": false, "error": "用户名或密码错误"}
{"ok": false, "error": "该账号已被禁用"}
```

**Token 说明**：
- 管理员 Token 有效期 24 小时
- 签名密钥为 `Admin.Password` 配置项
- Payload 包含 `admin_id`、`username`、`role`
