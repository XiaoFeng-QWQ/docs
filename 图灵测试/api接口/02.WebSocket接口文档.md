# WebSocket API 文档

> 项目：对面是AI吗  
> 协议：WebSocket  
> 数据格式：JSON（文本帧）  
> 基础URL：`wss://game.xfcode.top`  
> 心跳：客户端发送 `{"type":"ping"}`，服务端回复 `{"type":"pong"}`，10s 间隔，65s 超时断开  
> 更新日期：2026-10-06

---

## 通用约定

### 消息格式

所有消息均为 JSON 文本帧，以 `type` 字段区分消息类型：

```json
{"type": "消息类型", ...其他字段}
```

### WebSocket 端点总览

服务端在 `WebSocketHandler` 中按 **请求路径**（onOpen）与 **消息 type 前缀**（onMessage）双重路由。各端点前缀与 Handler 对照见文末附录。

### 通用消息类型

所有游戏模式均支持以下通用消息：

| type | 方向 | 说明 |
|------|------|------|
| `ping` | C→S | 心跳请求 |
| `pong` | S→C | 心跳响应 |
| `get_stickers` | C→S | 获取表情包差异更新 |
| `stickers_list` | S→C | 表情列表（有变更时） |
| `stickers_unchanged` | S→C | 表情无变化 |
| `error` | S→C | 通用错误 `{"type":"error","message":"..."}` |

### 时间字段约定

- 所有 `time` / `created_at` / `createdAt` 等时间字段均为 **Unix 秒级时间戳（int）**，展示格式由客户端自行解析。
- `duration` / `timeout` / `seconds_remaining` / `ttl` 等为 **相对时长（秒）**，非时间戳。

## 认证机制

所有 WebSocket 端点共用同一套身份认证体系，由 `BaseGameHandler` 统一实现。

### 连接阶段（onOpen）

WebSocket 连接建立时**不进行身份验证**，仅做以下检查：

1. **IP 提取** — 优先级：`CF-Connecting-IP` > `X-Forwarded-For` > `X-Real-IP` > `remote_addr`
2. **IP 去重**（可选，默认开启）— 同一 IP 已有活跃连接时关闭旧连接
3. **IP 级封禁检查** — 调用 `BanRepository::isBanned()`，被封则推送 `{"type":"error","message":"您已被管理员封禁"}` 并关闭连接
4. **全服公告推送** — 如有生效中的 Redis 广播，推送给新连接
5. **在线人数推送** — 非聊天室端点推送 `{"type":"online_count","count":N}`（在线数按 IP 去重）
6. **连接过载拒绝** — 服务过载时推送 `{"type":"error","message":"服务器繁忙，请稍后再试"}` 并关闭连接

真正的身份验证发生在客户端发送第一条业务消息时（如 `join`、`lobby_join`、`board_gomoku_join`、`soup_lobby`）。

### 业务消息认证（三级验证）

所有需要身份的消息均携带以下字段（三选一即可）：

| 字段 | 说明 | 优先级 |
|------|------|--------|
| `player_token` | 已有的 JWT Token（老玩家） | 最高 |
| `password` | 密码（新玩家注册/换设备恢复） | 中 |
| 仅 `nickname` | 昵称（兼容旧数据，需同设备 IP+FP 匹配） | 最低 |

#### Level 1：Token 验证（老玩家优先）

```
Client → Server: {type: "join", nickname: "小明", player_token: "eyJ..."}
```

- Token 格式：`base64(json_payload).hmac_sha256_sig`
- Payload 结构：`{player_id, exp(365天), iat, jti}`
- HMAC 密钥：玩家在数据库中的 `password_hash`（bcrypt）
- 验证内容：签名正确性 + 过期时间 + player_id 有效性

**Token 可用跨模式复用** — 同一 player_id 可在 `/ws`、`/ws/lobby`、`/ws/board/gomoku`、`/ws/board/go`、`/ws/soup` 等各端点之间通用。

#### Level 2：密码验证（新玩家/换设备）

```
Client → Server: {type: "join", nickname: "小明", password: "mypassword"}
```

- 按昵称查数据库，`password_verify($password, $record['password_hash'])`
- 密码正确 → 生成新 Token 并返回
- 密码错误 → 返回 `{"type":"error","message":"密码不正确"}`，不中断连接，可重试
- 昵称不存在 → 视为新玩家注册，自动创建身份

#### Level 3：仅昵称（兼容旧迁移数据）

```
Client → Server: {type: "join", nickname: "小明"}
```

- 按昵称查数据库
- 存在且同设备（IP + Fingerprint 匹配）→ 允许复用旧账号，生成新 Token
- 存在但设备不同 → 返回 `{"type":"error","message":"该昵称已被占用，请换一个或输入密码"}`
- 不存在 → 视为新玩家，自动创建

### 新玩家注册

当昵称在数据库中不存在时，自动触发注册流程：

1. 检查同 IP 账号数 ≤ 3（超出则拒绝，错误 `不允许创建多个账号！`）
2. 调用 `PlayerStatsRepository::createPlayer(nickname, ip, fp, password)` 创建记录
3. 密码使用传入的 `password` 或随机生成 `bin2hex(random_bytes(8))`
4. BCrypt cost 10 加密存储
5. 生成 JWT Token 返回给客户端

创建过于频繁时返回 `账号创建过于频繁，请稍后再试`。

### 在线唯一性

同一 `player_id` 通过 Redis `SETNX` 锁定（120s TTL），防止多地同时登录：

- 登录时 `claimOnlineLock()` 尝试获取锁
- 连接关闭时自动释放
- 获取锁失败 → 关闭已有连接，推送 `{"type":"system","text":"该账号已在其他地方登录，请先退出后再重试"}`

### 验证失败处理汇总

| 端点 | 消息类型 | 失败响应 type | 失败示例 | 连接 |
|------|---------|-------------|---------|------|
| `/ws` | `join` | `error` | `{"type":"error","message":"密码不正确"}` | 不断开 |
| `/ws/lobby` | `lobby_join` | `lobby_error` | `{"type":"lobby_error","text":"密码不正确"}` | close |
| `/ws/board/gomoku` | `board_gomoku_join` | `board_gomoku_error` | `{"type":"board_gomoku_error","data":"密码不正确"}` | 不断开 |
| `/ws/board/go` | `board_go_join` | `board_go_error` | `{"type":"board_go_error","data":"密码不正确"}` | 不断开 |
| `/ws/soup` | `soup_lobby` | `soup_error` | `{"type":"soup_error","message":"密码不正确"}` | 不断开 |
| `/ws/tempchat` | `temp_join` | `temp_error` | `{"type":"temp_error","text":"登录已失效，请重新登录"}` | close |
| 全部 | onOpen | `error` | `{"type":"error","message":"您已被管理员封禁"}` | close |
| 全部 | online lock | `system` | `{"type":"system","text":"该账号已在其他地方登录..."}` | close |

### Token 机制（内部）

```
生成: base64(json_encode({player_id, exp(365天), iat, jti(随机8字节)})) . "." . hmac_sha256(payload, password_hash)
验证: 解析 payload + sig → 查 DB 获取 password_hash → 重新计算 HMAC 对比
密钥: 每个玩家独立的 bcrypt password_hash
有效期: 365 天
```

### 1.2 匹配与对局流程

#### join（加入匹配）

**方向**：C→S

```json
{
  "type": "join",
  "nickname": "小明",
  "duration": 600,
  "fingerprint": "可选的设备指纹",
  "password": "密码（新玩家创建身份或恢复身份时）",
  "player_token": "已有的 token（已登录时）",
  "reconnect_session_id": "重连恢复时的 session_id"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `nickname` | string | 是 | 1-16 字符 |
| `duration` | int | 是 | 对局时长：`300`（5分钟）或 `600`（10分钟） |
| `fingerprint` | string | 否 | 设备指纹 |
| `password` | string | 条件 | 新玩家创建身份或恢复时 |
| `player_token` | string | 条件 | 已有 token 时，与 password 二选一 |
| `reconnect_session_id` | string | 否 | 断线重连恢复 |

**说明**：加入匹配队列。身份验证成功后进入等待。

## 2. 大厅聊天室

**WebSocket 路径**：`/ws/lobby`  
**Handler**：`LobbyChatWebSocketHandler`  
**前缀**：`lobby_`

大厅聊天室为常驻公共聊天室，支持文本 / 表情 / 图片 / 卡片分享、@ 提醒、拍一拍、点歌、MD 投票与管理员治理。消息广播有 64KB 上限保护（超大消息自动降级）。

### 2.1 连接建立

连接建立后**不立即下发**历史/在线列表，需先发送 `lobby_join` 完成身份验证。

`lobby_join` 通过后依次下发：

```json
{"type":"lobby_joined","nickname":"小明","player_id":"player_xxx","token":"eyJ...","sender_titles":[],"sender_special_titles":[]}
{"type":"lobby_history","messages":[...]}
{"type":"lobby_online_count","players":[{"fd":1,"nickname":"小明","player_id":"player_xxx","is_bot":0,"muted":0,"isolated":0}]}
```

并向其他在线用户广播进入通知（不发给本人）：

```json
{"type":"lobby_system","text":"小明 进入了聊天室"}
```

> **跨 Handler 复用**：棋类等待页可通过 `board_{game}_open_lobby_chat` 把棋局连接挂载进聊天室，同一 fd 参与广播与在线列表；此时聊天室侧的 `lobby_*` 消息由路由层按前缀转交。

#### lobby_chat（发送聊天消息）

**方向**：C→S

```json

  "type": "lobby_chat",
```

| `reply_to_name` | string | 否 | 回复对象的昵称 |
| `reply_to_text` | string | 否 | 回复消息的原文摘要（最多 100 字符） |

**触发条件**：已加入聊天室 + 未被禁言 + 未被孤立 + 通过频率限制。

**广播（普通文本）**：
```json
{
  "type": "lobby_chat",
  "id": 456,
  "sender_name": "小明",
  "sender_id": "player_xxx",
  "content": "大家好！",
  "msg_type": "",
  "is_bot": false,
  "sender_titles": [],
  "sender_special_titles": [],
  "reply_to": {"id":123,"name":"小红","text":"原始消息内容"},
  "mentions": ["小红"],
  "time": 1730000000,
  "created_at": 1730000000
}
```

**广播（含特殊 MD 语法）**：
```json
{
  "type": "lobby_chat",
  "id": 457,
  "sender_name": "小明",
  "sender_id": "player_xxx",
  "content": {
    "v": 1,
    "blocks": [
      { "t": "text", "text": "投票：" },
      { "t": "vote", "question": "今天午饭吃什么", "options": ["米饭", "面条"], "max": 1, "mode": "bar", "sync": true }
    ]
  },
  "msg_type": "markdown",
  "is_bot": false,
  "sender_titles": [],
  "sender_special_titles": [],
  "reply_to": null,
  "mentions": [],
  "time": 1730000060,
  "created_at": 1730000060
}
```

| 广播字段 | 类型 | 说明 |
|----------|------|------|
| `msg_type` | string | `markdown`（含特殊 MD 语法）/ 空字符串（普通文本）/ `card.share.record` / `card.invite.board.gomoku` / `card.invite.board.go` / `card.share.fate` |
| `content` | object\|string | `markdown` 时为 blocks 对象 `{"v":1,"blocks":[...]}`；普通文本时为纯文本原文；卡片消息时为卡片 JSON 对象 |
| `is_bot` | bool | 是否来自 BOT 网关 |
| `sender_titles` / `sender_special_titles` | string[] | 发送者佩戴标签 / 特殊标签 |
| `reply_to` | object\|null | 引用消息 `{id,name,text}` |
| `mentions` | string[] | 本条消息实际 @ 到的在线昵称 |
| `time` / `created_at` | int | Unix 秒级时间戳 |

## 3. 五子棋

**WebSocket 路径**：`/ws/board/gomoku`  
**Handler**：`GomokuHandler`（继承 `AbstractBoardGameHandler`）  
**前缀**：`board_gomoku_`

五子棋与围棋共用棋类对局外壳（`AbstractBoardGameHandler`）：身份验证、房间、观战、对局内聊天、再弈、断线判负流程完全一致，仅棋盘规则不同。消息类型由前缀动态拼装：`board_gomoku_` + 动作后缀。

### 3.1 连接建立

**服务端推送**（连接成功后）：

```json
{"type":"board_gomoku_connected"}
```

```json
  "data": {"r":7,"c":7,"color":1,"nextTurn":2}
}
```

#### game_over（游戏结束）

**方向**：S→C

```json
{
  "type": "board_gomoku_game_over",
  "data": {
    "winner": 1,
    "reason": "win",
    "winPath": [[3,3],[4,4],[5,5],[6,6],[7,7]]
  }
}
```

| 字段 | 说明 |
|------|------|
| `winner` | `1`=黑棋胜，`2`=白棋胜，`0`=平局 |
| `reason` | `"win"`（五连）、`"draw"`（棋盘下满平局）、`"认输"`、`"超时"` |
| `winPath` | 获胜的 5 个棋子坐标（非 `win` 时为空数组） |

### 3.4 断线处理

- 对局中断线 → 断线方判负，对手与观战者收到 `board_gomoku_opponent_disconnected`，房间删除，双方战绩异步落库
- 观战者断线 → 静默移除，不影响对局
- 对局已结束断线 → 仅清理连接绑定

## 4. 围棋

**WebSocket 路径**：`/ws/board/go`  
**Handler**：`GoHandler`（继承 `AbstractBoardGameHandler`）  
**前缀**：`board_go_`

对局外壳与五子棋完全一致（见 3.2 节棋类公共动作），将消息前缀替换为 `board_go_` 即可：`board_go_join` / `board_go_create_room` / `board_go_join_room` / `board_go_cancel_wait` / `board_go_surrender` / `board_go_timeout` / `board_go_request_rematch` / `board_go_chat_message` / `board_go_share_invite` / `board_go_open_lobby_chat` / `board_go_close_lobby_chat` / `board_go_error` / `board_go_opponent_disconnected`（邀请卡片 `card` 为 `board_go_invite`，`msg_type` 为 `card.invite.board.go`）。

## 5. 海龟汤

**WebSocket 路径**：`/ws/soup`  
**Handler**：`SoupWebSocketHandler`  
**前缀**：`soup_`  
**开关**：`Soup.Enabled`（默认开启）

海龟汤（真人房）为多人推理玩法：出题人（房主）持有汤底，猜题人提问，出题人判定。房间状态：`lobby`（大厅）→ `picking`（选题）→ `playing`（对局）→ `revealed`（结算）。

**防作弊**：汤底（`truth`/`key_points`/`hints`）仅下发给房主（出题人）与结算揭示时；猜题人端永远拿不到。

### 5.1 连接建立

**服务端推送**（连接成功后）：

```json
{"type":"soup_connected"}
{"type":"soup_room_list","rooms":[...]}
```

`online_count` 也会按通用逻辑推送。

### 5.2 身份与大厅

#### soup_lobby（进入大厅并拉取房间列表）

**方向**：C→S

```json
{
  "type": "soup_lobby",
  "fp": "设备指纹",
  "nickname": "小明",
  "password": "密码",
  "player_token": "已有 token"
}
```

**响应**（身份验证通过后）：
```json
{"type":"soup_joined","data":{"token":"eyJ...","player_id":"player_xxx","nickname":"小明"}}
{"type":"soup_room_list","rooms":[...]}
```

### 5.3 房间消息

#### soup_create（创建房间）

**方向**：C→S

```json

  "puzzle_id": 0
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `room_name` | string | 否 | 房间名（最多 24 字符），缺省为「昵称 的汤面房」 |
| `source` | string | 否 | 题目来源（如 `public`/`random`），配合 `puzzle_id` 可建房即选题 |
| `puzzle_id` | int | 否 | 指定题目 ID |

**响应**：
```json

```

**错误**（`soup_error`）：`你已在一个房间中`。

#### soup_join_room（加入房间）

**方向**：C→S

```json

```

同时广播 `soup_room` 房间快照。

**错误**（`soup_error`）：

| message 文案 | 触发场景 |
|--------------|----------|
| `你已在一个房间中` | 重复加入 |
| `房间不存在或已解散` | 房间码无效 |
| `对局已开始，无法加入` | 房间处于 playing/revealed |
| `房间已满` | 人数达到 `Soup.MaxPlayers`（默认 6） |

#### soup_pick（出题人选题）

**方向**：C→S

```json
{"type":"soup_pick","source":"random","puzzle_id":0}
```

**错误**：`只有出题人可以选题`、`对局进行中，无法更换题目`。

#### soup_ready（出题人开始）

**方向**：C→S


#### soup_leave（离开房间）

**方向**：C→S

```json
{"type":"soup_leave"}
```

**响应**：
```json
{"type":"soup_left"}
```

**说明**：房主离开 → 解散房间并通知所有成员（`房主已解散房间`）；猜题人离开 → 广播 `soup_system`「X 离开了房间」。

### 5.4 对局消息

#### soup_ask（猜题人提问）

**方向**：C→S

```json
{"type":"soup_ask","text":"他是意外死亡的吗？"}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `text` | string | 是 | 问题内容，最多 200 字符 |

**广播**：

```json
  "index": 1,
```

#### soup_ai_suggest（出题人请求 AI 判定建议）

**方向**：C→S


| 字段 | 类型 | 必填 | 说明 |

**响应**：


**错误**：`只有出题人可以请求 AI 建议`、`AI 建议已关闭`（`Soup.AiAssist=false`）、`当前不在对局中`、`没有待判定的提问`、`AI 暂时无法给出建议，请手动判定`。

#### soup_answer（出题人判定）

**方向**：C→S

```json
{"type":"soup_answer","question_id":1,"verdict":"yes","reason":"符合"}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `question_id` | int | 是 | 目标问题 ID |

**错误**：`只有出题人可以判定`、`当前不在对局中`、`无效的判定`、`提问不存在`、`「命中」只能用于汤底猜测`。

#### soup_guess（猜题人猜底）

**方向**：C→S


| 字段 | 类型 | 必填 | 说明 |

#### soup_giveup（出题人揭示汤底）

**方向**：C→S

```json
{"type":"soup_giveup"}
```

**错误**：`只有出题人可以揭示汤底`、`当前不在对局中`。


```json
{"type":"fate.opponent_done","data":{"status":"left"}}
```

## 7. 方块世界（2D 沙盒）

**WebSocket 路径**：`/ws/blockworld`  
**Handler**：`BlockWorldWebSocketHandler`  
**前缀**：`bw_`  
**开关**：`BlockWorld.Enabled`（默认关闭）

2D 多人沙盒世界。世界未加载就绪时拒绝连接。位置采用「客户端预测 + 服务端校验」：服务端不跑物理 tick，仅在收到上报时校验位移/碰撞；下行以 100ms（10Hz）批包聚合。

### 7.1 连接建立

**服务端推送**（连接成功后，要求世界已就绪）：

```json
{"type":"bw_connected"}
```

若世界未就绪：`{"type":"bw_error","data":"世界尚未就绪，请稍后再试"}` 并关闭连接。

### 7.2 消息协议

#### bw_join（进入世界）

**方向**：C→S

```json
{
  "type": "bw_join",
  "fp": "设备指纹",
  "nickname": "小明",
  "password": "密码",
  "player_token": "已有 token",
  "x": 100.5,
  "y": 40.0
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `fp` | string | 否 | 设备指纹 |
| `nickname` | string | 是 | 昵称 |
| `password` | string | 条件 | 新玩家/恢复身份时 |
| `player_token` | string | 条件 | 已有 token 时 |
| `x` / `y` | float | 否 | 期望出生点坐标（合法且无碰撞时采用，否则用世界默认出生点） |

**响应**：
```json
{"type":"bw_joined","player_id":"player_xxx","pid_hash":1234567890,"spawn":{"x":100.5,"y":40.0},"world":{"w":256,"h":128}}
{"type":"bw_pid_map","map":{"1234567890":"player_xxx"},"nick":{"player_xxx":"小明"}}
{"type":"bw_chunk","cx":6,"cy":2,"data":"..."}
```
**世界广播（给其他玩家）**：
```json
{"type":"bw_player_info","pidHash":1234567890,"pid":"player_xxx","nickname":"小明"}
```

**错误**：`世界人数已满，请稍后再试`、`您已被管理员封禁...`、身份验证错误。

#### bw_move（位置上报）

**方向**：C→S

```json
{"type":"bw_move","x":101.2,"y":40.0,"dir":2}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `x` / `y` | float | 是 | 坐标 |
| `dir` | int | 否 | 朝向（0-3） |

**纠偏**（位移超限/越界/穿墙时回拉到服务端权威位置）：
```json
{"type":"bw_correct","x":100.5,"y":40.0}
```
**错误**：`尚未进入世界`。

#### bw_dig（挖掘）/ bw_place（放置）

**方向**：C→S

```json
{"type":"bw_dig","x":100,"y":40}
```

```json
{"type":"bw_place","x":100,"y":40,"id":3}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `x` / `y` | int | 是 | 方块坐标 |
| `id` | int | 是（place） | 方块 ID |

**广播**：
```json
{"type":"bw_block","x":100,"y":40,"id":3}
```

**错误**：距自身超出 `ReachDistance` 等由服务端判定，返回 `bw_error`。

#### bw_chat（世界内聊天）

**方向**：C→S

```json
{"type":"bw_chat","text":"你好"}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `text` | string | 是 | 消息内容，最多 100 字符，最小间隔 800ms |

**广播**：
```json
{"type":"bw_chat","pidHash":1234567890,"nickname":"小明","text":"你好"}
```

#### bw_respawn（重生）

**方向**：C→S

```json
{"type":"bw_respawn"}
```

**响应**：`{"type":"bw_correct","x":...,"y":...}`（回到世界默认出生点）

### 7.3 服务器推送

#### bw_pack（移动批包）

100ms 周期性下发视野内玩家位置，二进制 base64 信封：

```json
{"type":"bw_pack","enc":"b64","data":"..."}
```

- 仅视野内（`AOIViewChunks`）且窗口内有位移的玩家进入批包；视野内仅 1 人时改发单条 `bw_move` JSON
- 二进制格式：`[count:1B] + N × [pidHash:4B][x:2B][y:2B][flags:2B]`，坐标量化为 1/8 方块（uint16）
- `flags`：bit0-1 朝向，bit2-3 动作（V1 恒为 0），bit4 是否为观察者自己

#### bw_chunk / bw_block / bw_player_info / bw_leave / bw_error

```json
{"type":"bw_chunk","cx":6,"cy":2,"data":"..."}
{"type":"bw_block","x":100,"y":40,"id":0}
{"type":"bw_player_info","pidHash":1234567890,"pid":"player_xxx","nickname":"小明"}
{"type":"bw_leave","pidHash":1234567890}
{"type":"bw_error","data":"错误描述"}
```

### 7.4 断线处理

玩家离开时世界内广播 `bw_leave`（携带 `pidHash`）。

## 9. Bot Gateway WebSocket

**WebSocket 路径**：`/bot`  
**Handler**：`BotGatewayWebSocketHandler`

Bot Gateway 是开放给第三方 BOT 客户端的 WebSocket 网关，BOT 可以以独立身份加入聊天室。BOT 连接建立后需要先鉴权，鉴权成功后自动加入聊天室。

### 9.1 鉴权流程

```
客户端 → 服务端: 连接 /bot
服务端 → 客户端: {"type":"bot_wait_auth"}
客户端 → 服务端: {"type":"bot_auth","player_id":"xx","key":"xx"}
服务端 → 客户端: {"type":"bot_auth_ok","nickname":"xx"} 或 {"type":"bot_error","message":"..."}
```

**步骤说明**：

1. 客户端连接 `ws://host/bot/`
2. 服务端返回 `{"type":"bot_wait_auth"}`，等待鉴权
3. 客户端发送鉴权消息 `bot_auth`
4. 服务端校验 `player_id` + `key` 是否匹配 `bot_list` 表且状态启用
5. 鉴权成功 → 自动以 BOT 身份加入聊天室 + 返回 `bot_auth_ok`
6. 鉴权失败 → 返回 `bot_error` 并关闭连接

> 未鉴权时仅接受 `bot_auth`，其它消息一律返回 `{"type":"bot_error","message":"请先发送鉴权消息 bot_auth"}` 并关闭连接。

### 9.2 消息协议

#### bot_auth（鉴权）

**方向**：C→S

```json
{
  "type": "bot_auth",
  "player_id": "玩家ID",
  "key": "bot_key"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `player_id` | string | 是 | 绑定 BOT 的玩家 ID（从 BOT 面板获取） |
| `key` | string | 是 | BOT 鉴权密钥（从 BOT 面板获取） |

#### bot_auth_ok（鉴权成功）

**方向**：S→C

```json
{
  "type": "bot_auth_ok",
  "nickname": "我的机器人"
}
```

| 字段 | 说明 |
|------|------|
| `nickname` | BOT 在聊天室中的昵称 |

#### bot_wait_auth（等待鉴权）

**方向**：S→C

```json
{"type": "bot_wait_auth"}
```

#### bot_error（鉴权失败）

**方向**：S→C

```json
{"type": "bot_error", "message": "BOT 鉴权失败：玩家ID或KEY不正确"}
```

#### bot_ping / bot_pong（心跳）

**方向**：C→S → S→C

```json
{"type": "bot_ping"}
```

**响应**：
```json
{"type": "bot_pong"}
```

**说明**：BOT 客户端应每 30 秒发送一次 `bot_ping` 保持连接。

### 9.3 鉴权后的消息

鉴权成功后，BOT 自动加入聊天室，所有消息直传聊天室（复用 `LobbyChatWebSocketHandler` 的全部能力）。BOT 发送的消息会自动携带 `_bot` 标记，前端据此识别为 BOT 消息。

**BOT 可发送的消息类型**：`lobby_chat`、`lobby_sticker`、`lobby_nudge` 等（与聊天室协议一致，见 2.2 节）。

**注意**：BOT 客户端无需发送 `lobby_join`，服务端在鉴权成功后已自动调用；客户端重复发送 `lobby_join` 会被忽略。

## 10. 临时聊天 TempChat WebSocket

**WebSocket 路径**：`/ws/tempchat`  
**Handler**：`TempChatWebSocketHandler`  
**前缀**：`temp_`

临时聊天（1v1 私密房）系统，支持邀请制、一次性房间、断线重连等功能。**强制要求登录账号**（无有效 token 直接拒绝），不支持游客。

### 10.1 连接建立

连接建立后不发送额外消息，客户端需发送 `temp_join` 加入临时聊天。

### 10.2 消息协议

#### temp_join（加入临时聊天）

**方向**：C→S

```json
{
  "type": "temp_join",
  "nickname": "小明",
  "player_token": "eyJ..."
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `nickname` | string | 否 | 显示昵称（服务端以账号昵称为准），最多 12 字符 |
| `player_token` | string | 是 | 玩家 Token（必须登录，禁止游客） |

**说明**：临时聊天强制要求登录账号，无有效 token 将被拒绝并关闭连接。

**错误**（`temp_error` 后关闭连接）：`临时聊天需要登录账号，请先登录`、`登录已失效，请重新登录`、`昵称无效，无法加入临时聊天`。

**响应**：
```json
{
  "type": "temp_joined",
  "nickname": "小明",
  "has_identity": true,
  "player_id": "player_xxx"
}
```

#### temp_search（搜索在线用户）

**方向**：C→S

```json
{"type": "temp_search", "keyword": "小"}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `keyword` | string | 是 | 搜索关键词，最大 20 字符 |

**响应**：
```json
{
  "type": "temp_search_result",
  "users": [
    {"player_id": "abc...", "nickname": "小红", "status": "online"}
  ]
}
```

#### temp_invite（发起邀请）

**方向**：C→S

```json
{"type": "temp_invite", "target_player_id": "abc..."}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `target_player_id` | string | 是 | 目标玩家 ID |

**响应**：
```json
{"type": "temp_invite_sent", "ok": true, "invite_id": "iv_xxx"}
```

**错误**：
```json
{"type": "temp_invite_sent", "ok": false, "error": "对方不在线"}
```

| error 文案 | 触发场景 |
|------------|----------|
| `缺少目标用户` | 目标 ID 为空 |
| `不能邀请自己` | 邀请自己 |
| `对方不在线` | 目标不在线 / fd 失效 |
| `对方正在对局中，无法邀请` | 目标状态 `ingame` |
| `对方正在临时聊天中` | 目标状态 `busy` |

**被邀请方收到**：
```json
{
  "type": "temp_invite",
  "invite_id": "iv_xxx",
  "from_name": "小明",
  "from_player_id": "abc...",
  "timeout": 60
}
```

**说明**：邀请有效期 60 秒，超时自动取消。超时后邀请方收到 `{"type":"temp_invite_result","ok":false,"error":"邀请超时，对方未做出回应"}`，被邀请方收到 `{"type":"temp_invite_expired","text":"邀请已过期"}`。

#### temp_invite_resp（回应邀请）

**方向**：C→S

```json
{"type": "temp_invite_resp", "invite_id": "iv_xxx", "accept": true}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `invite_id` | string | 是 | 邀请 ID |
| `accept` | bool | 是 | `true`=接受，`false`=拒绝 |

**错误**（`temp_invite_result`）：`邀请不存在或已过期`、`无权回应此邀请`。

**拒绝**：
- 邀请方收到：`{"type":"temp_invite_result","ok":false,"error":"对方拒绝了您的邀请"}`
- 被邀请方收到：`{"type":"temp_invite_dismissed"}`

**接受（双方进入房间）**：

邀请方收到（`pending_join=true` 表示邀请方不在临时聊天连接上，需跳转 `/temp-chat` 后发送 `temp_rejoin` 进房）：
```json
{
  "type": "temp_room_created",
  "room_id": "tr_xxx",
  "peer_name": "对方昵称",
  "peer_player_id": "对方ID",
  "pending_join": false
}
```
被邀请方收到：
```json
{
  "type": "temp_room_created",
  "room_id": "tr_xxx",
  "peer_name": "对方昵称",
  "peer_player_id": "对方ID"
}
```

**错误**（`temp_invite_result`）：`对方状态已变化，无法进入`。

#### temp_rejoin（断线重连）

**方向**：C→S

```json
{
  "type": "temp_rejoin",
  "room_id": "tr_xxx",
  "nickname": "小明",
  "player_token": "eyJ..."
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `room_id` | string | 是 | 房间 ID |
| `nickname` | string | 否 | 重连后显示的昵称 |
| `player_token` | string | 是 | 玩家 Token（必须匹配房间中的身份） |

**说明**：断线 60 秒内可重连恢复。重连必须凭 token 匹配房间中的 a/b 一方身份，禁止纯昵称匹配（防冒认）。

**响应**：
```json
{
  "type": "temp_room_created",
  "room_id": "tr_xxx",
  "peer_name": "对方昵称",
  "peer_player_id": "对方ID",
  "rejoined": true,
  "history": [{"sender_name":"小明","content":"你好","time":1730000000}]
}
```

| 字段 | 说明 |
|------|------|
| `rejoined` | 标记为重连恢复 |
| `history` | 最近 50 条消息历史 |

**错误**（`temp_closed`）：`房间已关闭`、`房间校验失败`。

**对方收到**：
```json
{"type": "temp_system", "text": "小明 已重新连接"}
```

#### temp_chat（发送消息）

**方向**：C→S

```json
{
  "type": "temp_chat",
  "content": "你好！",
  "sticker_id": "表情ID",
  "sticker_url": "表情URL"

```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `content` | string | 条件 | 文本内容，最大 1000 字符 |
| `sticker_id` | string | 否 | 表情 ID |
| `sticker_url` | string | 否 | 表情 URL（缺失时服务端按 `sticker_id` 解析） |

**说明**：`content`、`sticker_id`、`sticker_url` 至少填一个。消息写入 Redis LIST（保留最近 500 条，TTL 7200 秒，房间关闭即删）。

**广播（双方收到）**：
```json

  "time": 1730000000,

```

| 字段 | 说明 |
|------|------|
| `time` | Unix 秒级时间戳 |
| `player_id` / `avatar` | 仅账号玩家携带 |
| `sticker_id` / `sticker_url` | 表情消息携带 |

若房间处于非 active 状态，返回 `{"type":"temp_system","text":"房间不存在或已关闭"}`。

### 10.3 服务器主动推送

| type | 说明 | 关键字段 |
|------|------|----------|
| `temp_joined` | 加入成功 | `nickname`、`has_identity`、`player_id` |
| `temp_search_result` | 搜索结果 | `users[]` |
| `temp_invite` | 收到邀请 | `invite_id`、`from_name`、`from_player_id`、`timeout` |
| `temp_invite_sent` | 邀请发送结果 | `ok`、`invite_id`、`error` |
| `temp_invite_result` | 邀请处理结果 | `ok`、`error` |
| `temp_invite_expired` | 邀请已过期 | `text` |
| `temp_invite_dismissed` | 邀请已关闭 | — |
| `temp_room_created` | 进入房间/重连 | `room_id`、`peer_name`、`peer_player_id`、`pending_join`、`rejoined`、`history[]` |
| `temp_chat` | 聊天消息（广播） | `sender_name`、`content`、`sticker_id`、`sticker_url`、`time`、`player_id`、`avatar` |
| `temp_history` | 历史消息加载 | `messages[]`、`offset`、`has_more` |
| `temp_system` | 系统提示 | `text` |
| `temp_closed` | 房间关闭 | `reason`、`text` |
| `temp_report_result` | 举报结果 | `ok`、`message`、`error` |
| `temp_error` | 错误提示 | `text` |
| `temp_pong` | 心跳响应 | — |

### 10.4 断线处理

- 断线 60 秒内可重连恢复（通过 `temp_rejoin`）；对方收到 `{"type":"temp_system","text":"X 断开了连接，60秒内未重新连接将自动关闭房间"}`
- 重连时下发最近 50 条消息，更早的可向上滚动加载
- 超时未重连自动关房（`对方超时未重连，房间已自动关闭`），消息不保存
- 双方均离线时立即关房（`双方均离线，房间已自动关闭`）
